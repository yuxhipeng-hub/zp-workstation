## P0-2 失败路径测试包

**现状**

E2E 以正常路径为主（19 条）；0.6.1 的下载器事故说明失败路径没有测试兜底。
下面四类失败路径已补单元测试，真机升级仍需人工验证。

**需要覆盖的失败路径（每类至少一条）**

- 从旧版原地升级，包括旧下载器本身有缺陷时的提示与手动安装引导。
- 备份损坏、备份生成中途中断、密码错误。
- 资料库根目录迁移中途失败与回滚。
- 并发写入 `workspace.json`。
- 磁盘满或目录无权限。
- 模型接口超时、429、断流。

**进度**

- [x] 备份：损坏的普通/加密包、清单损坏、缺清单、格式不支持、无效工作区数据；
      失败时保持当前工作区不变，并把 JSZip / JSON 的原始错误换成中文提示。
- [x] 并发写入 `workspace.json`：写入失败保留旧文件、陈旧 `.tmp` 不影响读取、
      连续保存后文件仍可解析、损坏文件先留 `workspace.corrupt-*.json` 再回退默认值。
- [x] 资料库根目录迁移中途失败：复制失败时设置与工作区路径保持不变、原文件仍在；
      目标嵌套在当前目录内会被拒绝；含 junction 等特殊文件时保留旧目录并报告原因。
- [x] 模型接口超时、429、断流：401/403/404/429/5xx 映射成中文提示；超时与连接失败、
      截断或非 JSON 响应都有用例，全部走注入的 `fetchImpl`，不访问真实模型。
- [ ] 从 0.6.0 原地升级的真机验证（需要干净 Windows 用户环境）。
- [ ] 磁盘满或目录无权限（视可模拟性决定是否做）。

**验收标准**

- [ ] 每类都有单元测试或 E2E，并且跑在 CI 里。
- [ ] 失败时用户能看到可理解的中文提示，不出现静默失败或卡死。
- [ ] 新增测试能复现对应缺陷，而不是只覆盖代码分支。

## 推进规则

1. 一次只做一项，开 `codex/*` 分支，走 PR，CI 过了再合。
2. 每项完成后更新本文件的「状态总览」，并在 `docs/HANDOFF.md` 留一行记录。
3. 不为了清债务做一次性大爆炸重构；每步都保持可发布。
