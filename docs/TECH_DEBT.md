- 第一步只拆三个页面：模型配置、资料库、设置。

**进度**

- [x] 第 1 步：模型配置页已迁到 `src/renderer/pages/model-settings.js`，`main.js` 只保留
      路由映射、共享 helper 和动作转发（`getModelSettingsPage()`）。
- [x] 第 2 步：设置页渲染已迁到 `src/renderer/pages/settings.js`；`reset-settings`、
      `choose-experiment-dir` 等页面动作仍在 `main.js`，等共享 UI helper（任务条、主题、
      workspace 应用）抽出来后随下一步一起迁。
- [x] 第 3 步：资料库页渲染已迁到 `src/renderer/pages/experiments.js`；`main.js` 从 6594 行
      降到 5993 行，阶段一目标达成。

**验收标准**

按阶段验收，不再要求一步降到 3000 行：

- [x] 阶段一（模型配置、设置、资料库三页）：`main.js` 从 6594 行降到 6000 行以内（当前 5993）。

- [ ] 每个阶段现有单元测试和 18 条 E2E 全绿，PR 附 CI 链接。
- [ ] 不改动现有 DOM 结构、类名和视觉表现；拆分 PR 里不顺手改行为。

**预估**：阶段一 3–5 天；阶段二按页面单独估。

## P0-2 失败路径测试包

**现状**

18 条 E2E 全部是正常路径；0.6.1 的下载器事故说明失败路径没有测试兜底。

**需要覆盖的失败路径（每类至少一条）**

- 从旧版原地升级，包括旧下载器本身有缺陷时的提示与手动安装引导。
- 备份损坏、备份生成中途中断、密码错误。
- 资料库根目录迁移中途失败与回滚。
- 并发写入 `workspace.json`。
- 磁盘满或目录无权限。
- 模型接口超时、429、断流。

**进度**

- [x] 备份：损坏的普通/加密包、清单损坏、缺清单、格式不支持、无效工作区数据；
      失败时保持当前工作区不变，并把 JSZip / JSON 的原始错误换成中文提示。
- [x] 并发写入 `workspace.json`：写入失败保留旧文件、陈旧 `.tmp` 不影响读取、
      连续保存后文件仍可解析、损坏文件先留 `workspace.corrupt-*.json` 再回退默认值。
- [x] 资料库根目录迁移中途失败：复制失败时设置与工作区路径保持不变、原文件仍在；
      目标嵌套在当前目录内会被拒绝；含 junction 等特殊文件时保留旧目录并报告原因。
- [ ] 模型接口超时、429、断流。
- [ ] 从 0.6.0 原地升级的真机验证（需要干净 Windows 用户环境）。
- [ ] 磁盘满或目录无权限（视可模拟性决定是否做）。

**验收标准**

- [ ] 每类都有单元测试或 E2E，并且跑在 CI 里。
- [ ] 失败时用户能看到可理解的中文提示，不出现静默失败或卡死。
- [ ] 新增测试能复现对应缺陷，而不是只覆盖代码分支。

## P1-1 失败诊断包导出

**现状**

只有本地 `workbench.log`。用户报问题时，需要远程指导找日志路径，且日志目录可能已被更换。

**目标**

设置页提供「导出诊断信息」：日志尾部、应用版本、系统版本、主题与设置（脱敏）、
资料库路径概览，打成 zip 由用户自己保存，不上传。

**验收标准**

- [ ] 导出的包不含 API Key、模型 Key、绝对用户路径之外的隐私数据。
- [ ] 包内有一个 `README.txt` 说明每份文件是什么。
- [ ] 有单元测试覆盖脱敏逻辑。

## 推进规则

2. 每项完成后更新本文件的「状态总览」，并在 `docs/HANDOFF.md` 留一行记录。
3. 不为了清债务做一次性大爆炸重构；每步都保持可发布。
