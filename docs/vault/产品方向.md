# 产品方向

> [!abstract] 一句话
> ZP Workbench 是学生自己的课程与学习数据主库：课表、作业、资料和备份都在这，
> 它不替 DeepSeek Harness 桌面端干活。

## 定位

一个 Windows 桌面的学习数据工作台。核心是把学习数据集中到本地、结构化管理起来，
并且能把一条作业整理成结构化提示词交给模型用。数据存在本机 `workspace.json`，
写入前自动备份，不依赖云端服务。

## 目标用户与场景

- 主体用户是学生，尤其是课表、作业和资料都要自己管的人。
- 典型动作：导入一份 Excel/WPS 课表，记录作业和资料，需要时翻回来，把作业导出成提示词给模型。
- 使用频率高的时间点是开学导课表、每周排作业、考前翻资料。

## 能力边界

| 做                               | 不做                                     |
| -------------------------------- | ---------------------------------------- |
| 课程、课表、作业、资料库和备份   | 不再安装、更新或启动 DSH 运行时          |
| 把一条作业整理成结构化提示词     | 不再管 Skills、插件、模型连接和版本通道  |
| 本工作台自身的版本检查与下载线路 | 不再做通用桌面 Agent、应用托管和窗口控制 |
| 本地优先，写前备份               | 不做课堂协作、云端同步和多用户           |
| 资料库负责归档、分组和查找       | 不抽取资料库文件正文，也不把它拼进提示词 |

## 和 DeepSeek Harness 的分工

2026-10-14 的分工调整：官方 DSH 桌面端负责运行时安装、更新、模型和插件；
ZP Workbench 只做学习数据，DSH 降级为数据消费者。工作台里的"替官方端干活"的部分
（运行时、版本通道、插件管理、Skills 中心、模型连接）已经删除或正在删除，
备份里的技能改成直接打包 DSH 的技能目录。

## 已经定下的边界

- 知识点与复习板块不回来：数据里没有复习对象，硬做只是换个名字的待办清单。
- 资料库分类只用本地规则。Jev 后端已删除，"用模型猜课程"暂时没有实现路径。
- 与 DSH 彻底解耦：连路径解析（DshManager）也已删除，工作台只通过"复制提示词"把数据交出去。
- AI 资讯只在应用内阅读，不写入资料库，也不进导出和备份。
- 资料库不做提示词：文件正文永远不进模型上下文。提示词只由作业收件箱按作业自身的字段拼出来，
  "抽出正文给模型"这条路 2026-10-15 明确不做，别再提。
