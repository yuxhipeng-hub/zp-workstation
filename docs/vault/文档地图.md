# 文档地图

仓库资料搬进 vault 之后的结构、阅读顺序，以及每份东西什么时候该看。

## 结构

| 文件夹      | 放什么                                       |
| ----------- | -------------------------------------------- |
| `00 索引`   | 首页、这份地图、全部文档表和资料关系画布     |
| `10 产品`   | 定位、交接说明、变更时间线、待办             |

| `99 元数据` | 生成规则、来源映射、同步方式                 |

## 阅读路径

### 第一次接手这个项目

1. [[产品方向]]：先知道这是个什么东西、不做什么。
2. [[交接说明]]：现在停在哪个版本、哪条分支、下一步是什么。
3. [[DSH 接手手册]]：DSH 环境、架构、数据红线、测试矩阵和接手检查表。
4. [[开发框架]]：分支怎么开、架构边界在哪、门禁有哪些。
5. [[仓库约定]]：开工顺序和改动要求。

### 日常改代码

- 开工读 [[交接说明]]，收尾更新它，并把决策写进 [[决策记录]]。
- 在 DSH 中开发时，同时看 [[DSH 接手手册]]。
- 碰用户数据结构时看 [[开发框架]] 的数据版本与迁移那一节。
- 长线程开始变贵时看 [[上下文与成本]]。

### 发版本

[[发布与更新]] 是完整流程；[[交接说明]] 里有当前版本和目标分支。

### 改界面

[[设计系统（中文）]] 是实现规范，[[设计系统（英文）]] 是同一套东西的英文版，
[[Raycast 参考]] 只是外部样本，用来找手感，不是本项目的规范。
