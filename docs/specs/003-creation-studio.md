# 创作工作室 v1

入口为「工具 → 创作工作室」。独立于 PPT 工作室。下文为保留兼容的手动流程与外部协议1；
默认不调用模型、不发送素材。2026-11-07新增可主动启用的[视频制作流程](006-creation-video-pipeline.md)，
其实际执行与费用边界见[视频制作使用说明](../CREATION_VIDEO_GUIDE.md)。
本轮不制作《100元公司》或粒子文字。

## 界面设计（2026-11-07）

- 背景直接作为项目画布，创作路由不套 `route-canvas` 外框。页面内不使用项目侧栏或常驻属性栏。
  全页直接透出应用 `#app` 已有点阵；标题栏、工具栏、工作室根容器和项目树均透明。
  内部滚动区不再另画点阵或铺实色，避免局部贴片、点距和网格起点不一致；编辑框与菜单保留纯色浮层。
  创作页的全局导航缩成图标栏，顶栏压缩；离开该页恢复其他页面布局。
- 采用纵向树形大纲：项目→视频→七个编号步骤；名称、负责人和记录状态按列对齐，不使用七宫格卡片。
  不显示重复的「制作步骤/负责人/状态」列头、层级路径和保存常识提示；保留具体负责人、状态及错误反馈。
  大纲随窗口加宽至1440px并水平居中，步骤分支沿用可用宽度；窄窗口自动收缩。
  项目标题直接放在背景上，视频用真实已登记图片作小缩略图，没有图片时显示视频图标。
  初始仅显示项目；项目、视频和镜头分支分别展开，多个视频可以同时展开。展开分支不执行任务。
  点步骤只展开该项，再次点击收起；需求编辑会收起步骤详情。审核与生成使用独立内容，
  即使尚未启用视频流程，也按具体步骤显示入口；「全部制作工具」保留完整导航。
- 分镜步骤下显示真实镜头叶节点；点镜头只打开该镜头编辑框，不重复全片镜头导航。草稿按视频/镜头隔离。
  仅一个编辑框激活，其余分支保持原展开状态；方向键移动/展开/收起，Esc关闭编辑框并返回来源节点。
- 编辑框与菜单使用紧凑、无描边的整块底色，保留背景画布。需求框最大320px宽，默认不超过260px高，
  展开设置最多312px高；标题栏只保留任务名称和关闭图标，名称直接输入，目标与阶段在折叠区内并排显示。
  制作详情与步骤工作页沿分支可用宽度展开，利用右侧空间，以查看具体过程、镜头和版本为主；
  用户直接在Codex主窗口沟通，工作页移除内嵌导演聊天。独立审核的连接/模型/记录仅在审核与后期步骤按需展开。
  工作页不设480px高度上限，随画布统一滚动；
  需求小框仍随窗口缩小并在框内滚动。步骤工作页位于职责节点下方，标题与收起操作放在内容顶部。
  宽屏左侧为最大520px的紧凑编辑区，右侧直接显示已保存的创作要求、故事、分镜正文/时间段和实际图片/视频版本；
  镜头编辑时右侧只显示当前镜头。窄屏上下排列。无内容时用短状态，不用大占位框。
  加宽不放大间距：表单行距10px、列距16px；制作文本框空白为单行，按内容自适应至180px，删除后缩回。
  展开、收起及切换不自动滚动定位；保持当前画布位置，编辑焦点返回也不滚动。仅内容缩短到边界时自然夹紧。
  小框内容长时先滚动框内；内容短或到达边界时，滚轮继续作用于画布，避免滚动被困住。
  所有文本框取消右下角拖拽缩放手柄，保持编辑和滚轮浏览能力。
  创作要求空白时只占一行，随输入、换行和自动折行增高，删除后缩回；高度最多112px，之后在输入区滚动。
  草稿恢复和保存后重开也按内容计算高度，不预留空白行。
- 项目与视频使用加号创建，需求框以标题、创作要求为主，目标与阶段按需展开。
  项目名称旁放加号与三点菜单；项目需求、归档和移除收进菜单。视频需求与完整工具使用名称旁的图标入口。
  三点菜单使用贴近触发器的纵向主题浮层，不占树形布局空间；支持方向键、Home/End、Esc/Tab和点击外部关闭。
  菜单先隐藏测量和定位，同一次更新中显示；不从默认位置平移动画，避免初次打开或重开时闪影。
  制作阶段使用同主题的八项选择浮层，支持选中勾、方向键、Home/End、Esc/Tab；选择后写入原有阶段字段并保留草稿。
  编辑框紧跟对应项目/视频标题，完整工具位于步骤列表之前；同一入口再次点击收起，草稿继续保留。
  编辑区聚焦使用细灰色底线，不给输入框或外层标签添加蓝色描边。
  保存成功自动收起，原图标入口重新编辑；未保存草稿按对象独立保留在当前页面内存中。
- 视频工作页按需出现并可收起，保留视频制作、总览、作品与版本、修改意见、发布复盘入口。
  保存等主要操作使用透明底文字按钮，保留图标、悬停和键盘焦点提示，不使用突兀的白色填充。
  画布、工作页和文本区的滚动条轨道透明，保留可见滑块与滚轮衔接。
  视频行铅笔图标编辑名称与创作要求；「制作工具」图标打开完整工作区，两入口提供悬停说明。
  输入保持细底线样式，缩短默认输入高度和区块间距；宽屏总览并排展示作品预览与制作信息。
  分镜默认仅显示目的、时长与故事，其他参数逐项展开。
  创意简报保存成功收起工作页，失败保留输入与错误反馈。
- 职责：Codex导演负责策划与分镜，图片工具/用户负责图片，独立Codex审核负责复核，
  视频模型负责生成，FFmpeg负责后期，用户负责最终验收。显示具体记录状态，不按阶段伪造执行进度。
  Codex沿用现有主进程后台会话；页面不遥控外部Codex窗口，付费与工具确认边界保持原状。
  视频行显示「手动阶段：… · N 个作品版本」；阶段是人工标记，版本数统计已登记的图片、视频等产物，不能表示执行进度或成片数量。
- 画布支持空白拖动平移、滚动、60%–150%缩放与重置；窄窗口在画布内部滚动，避免撑破应用。
  缩放和重置作为紧凑控件固定在窗口右下角，不再显示整行底栏或左侧拖动提示。
  检查深浅主题、长名称、键盘操作、保存后焦点返回和减少动态效果。
- 点击步骤只更新一次。按项目/视频/步骤识别并复用DOM，不重建未变化的画布对象和已解码媒体。
  状态轮询只更新文字，不替换步骤按钮；图片缓存避免切换步骤时回到占位图。文件健康仍通过主进程重新核对。
- 鼠标展开使用120ms局部过渡，内容同步出现即可操作；不淡出整张画布，不等待动画结束。
  快速切换取消上一段过渡；键盘与减少动态效果模式跳过过渡。项目、视频和步骤分别控制展开状态。
- 浏览器预览为独立内存项目与示例封面，可创建项目/视频、编辑需求与简报，刷新即重置。
  文件、模型、付费提交、后期使用桌面应用，不接触真实用户工作区或服务。

## 使用流程

1. 新建项目，通过项目旁加号添加视频，填写创作要求并保存；点击视频展开步骤，进入工作页。
2. 从系统选择器导入图片、MP4、UTF-8 Markdown/TXT；或关联制作目录，点击「刷新项目记录」。
3. 「作品与版本」切换同一作品分组的版本，设置选定版本；图片并排查看，视频可同步定位秒数。
4. 「修改意见」取当前播放时间或手动输入秒数，填写原始问题与期望，标记必须修改/建议优化。
   可以筛选、按时间或优先级排序，复制或导出 Markdown 给外部执行者。
5. 导入修复版本，关联同一作品分组的版本，选择待复查；人工复查后选择已解决并保存。
   原始反馈与状态处理历史均保留。必须修改的意见关闭后，用户可明确点击确认版本验收。
6. 「发布复盘」手动填写平台、时间、成片版本、链接、耗时、支出与经验；每次观察独立添加指标快照。
   未知值为空/null，明确填写 0 才代表零。
7. 更多菜单支持归档、重新打开、移除记录；移除前明确提示，原文件和外部目录不删除。

## 数据与备份

`workspace.json.creationProjects` 默认空数组；沿用 WorkspaceStore 自动备份、临时文件写入与原子替换。
保存失败回滚工作室内存记录。旧工作区、旧快照和旧完整备份缺少此字段时正常打开。

Project 包含身份、名称、`kind`、`parentId`、目标、简报、八个制作阶段、目录、外部身份、来源版本、时间、归档、选定版本与活动。
`kind=project` 为顶层分组，`kind=video` 可通过 `parentId` 关联顶层项目；仅两级。
旧记录默认 `video` 且无父级，界面将它作为旧项目的原视频呈现，保留原ID、媒体、意见和制作记录。
清洗时将失效、嵌套、自引用、循环父关系提升到顶层，不丢弃视频。移除有子视频的项目会被拒绝。
归档顶层项目隐藏其所有视频，不改各视频独立归档标记；取消项目归档仍保留视频之前的归档状态。
Task 包含身份、目标、任务状态、产物关联、阻塞原因及时间；第一版从外部结构记录导入。
Run 包含独立执行身份、来源、说明、状态、任务、起止与心跳时间、帧数、错误和可选资源采样。
Artifact 包含独立版本身份、作品分组、类型、标签、路径/本机 URL、来源、来源版本、SHA-256、大小、任务/执行与人工验收记录。
Review 固定关联原产物版本，可选秒数，保留问题、期望、优先级、状态、修复版本摘要与处理历史。
Publication 固定关联发布版本，保存发布时间、链接、耗时/支出/经验，以及带独立观察时间的指标快照。

所有结构通过字段白名单清洗，不保存外部记录的未知字段（如 apiKey、env、command）。
自由填写的简报、错误或意见不要包含密钥；执行器必须在写入前脱敏。
项目与视频合计最多 100 条，每视频每类记录最多 500 条，活动保留最近 80 条。记录过多拒绝保存，不静默覆盖旧版本。

视频、图片、源码、缓存与权重不写入主数据，也不打包到工作室备份；工作室备份只保存索引、意见和发布记录。
外部媒体请另行备份。现有「包含资料文件」仍仅适用于资料库，不代表包含创作媒体。
恢复后目录/文件失效会单独提示；不会自动扫描磁盘寻找文件。

## 外部记录协议 1

在用户明确关联的目录下放置固定名称 `workbench-record.json`，UTF-8 JSON，最大 1 MB。
可直接试用的独立目录见 [`../examples/creation-record/`](../examples/creation-record/README.md)：
新建空项目后关联这个目录并刷新。不会自动插入正式工作区。

```json
{
  "schemaVersion": 1,
  "projectId": "my-project",
  "sourceVersion": "git-sha-or-manual-source-1",
  "updatedAt": "2026-11-05T12:00:00Z",
  "tasks": [{ "id": "render", "goal": "输出第一个版本", "status": "review" }],
  "runs": [
    {
      "id": "run-1",
      "source": "local-render-script",
      "taskId": "render",
      "status": "completed",
      "description": "真实执行完成后才写此状态",
      "startedAt": "2026-11-05T11:59:00Z",
      "endedAt": "2026-11-05T12:00:00Z",
      "updatedAt": "2026-11-05T12:00:00Z",
      "frames": 240,
      "totalFrames": 240
    }
  ],
  "artifacts": [
    {
      "id": "film-v1",
      "family": "成片",
      "type": "video",
      "label": "v1",
      "path": "output/film-v1.mp4",
      "taskId": "render",
      "runId": "run-1",
      "sourceVersion": "git-sha-or-manual-source-1",
      "createdAt": "2026-11-05T12:00:00Z"
    }
  ]
}
```

上例用于说明字段，成片路径应指向你实际生成的文件，不能以样例伪造执行。
`schemaVersion`、`projectId`、`updatedAt`、三个数组是必填项，空数组合法。
项目/记录 id 为非空且不超过 100 字符的稳定字符串，同类 id 不重复。任务与执行状态允许
`pending/running/review/blocked/completed/failed/cancelled/interrupted/unknown`。
执行必须提供有效 `updatedAt`；有 `totalFrames` 时需为正整数，`frames` 为 0 至总数的整数。
不提供帧数就不显示百分比。`taskId/runId/artifactId` 引用必须存在。
可选资源字段为 `memoryMB/vramMB/sampledAt/scope`，范围应说明进程、渲染器或设备；未提供显示未提供。
Task 可提供 `createdAt/updatedAt/blockedReason/artifactId`，Run 可提供 `error`（已脱敏）。

产物 `type` 支持 `image/video/text/interactive`，版本 `label` 必填，`family` 默认作品。
非互动作品的 `path` 必须为关联目录内相对路径；拒绝绝对路径、`..`、NTFS 流与越界符号链接。
图片支持 PNG/JPEG/WebP（最多 50 MB），视频支持 MP4（最多 4 GB），文字最多 1 MB。
检查扩展名、文件头、大小、读取权限和写入期间变化；MP4 编码是否能播放由 Electron 解码器决定。
缺失文件保留路径记录并显示文件已丢失。文件第一次生成后若摘要变化，应写新的产物 id。

互动产物使用 `url`，只接受无凭据、无查询与片段的 `http://127.0.0.1:端口/路径`、`localhost` 或 `[::1]`。
用户显式点击后在外部默认浏览器打开，不内嵌运行、不注入 preload、不负责启动服务器，也不能凭 URL 验收。

刷新先校验整份记录，再一次性提交。按外部项目身份+记录 id 生成稳定内部身份，重复刷新不会重复创建。
已有版本的摘要、路径、URL 或来源版本变化时拒绝本次刷新，要求使用新产物 id；保留旧版本和反馈。
较旧时间、错误 JSON、错误引用、无权限与异常路径均保留最后有效数据，并显示原因。
项目阶段和人工验收状态不能由协议修改。BRIEF/HANDOFF/QA/README.md 可只读查看，不解析成执行状态。

执行器写入时使用临时文件与原子 rename，产物写完后再登记；可先保留旧 artifacts 列表并追加新版本。
工作室不监听目录，需手动刷新。外部记录中的 running 仅表示已收到声明，超过 120 秒无心跳、未来时间异常，
或 Workbench 重启后未再次刷新，显示「状态待确认」。界面每 30 秒更新陈旧状态，不探测进程、不推断成功失败。
完成、失败、取消、中断与未知分别展示；显示实际帧数不代表最终验收。

## 预览与验收边界

媒体经主进程校验后发放会话级 `studio-media` 能力 URL，流式读取以支持 MP4 seek，不转 Base64。
请求只服务已登记媒体，检查索引与文件 size/mtime，拒绝文件变动；渲染层无文件系统或任意命令能力。
