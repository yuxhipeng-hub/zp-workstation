# 创作工作室 v1

入口为「工具 → 创作工作室」。独立于 PPT 工作室，不调用模型、不发送素材、不启动外部项目。
本轮不制作《100元公司》或粒子文字。

## 使用流程

1. 新建项目，填写名称、目标、简报与制作阶段；保存成功才显示「本地保存」。
2. 从系统选择器导入图片、MP4、UTF-8 Markdown/TXT；或关联制作目录，点击「刷新项目记录」。
3. 「作品与版本」切换同一作品分组的版本，设置选定版本；图片并排查看，视频可同步定位秒数。
4. 「修改意见」取当前播放时间或手动输入秒数，填写原始问题与期望，标记必须修改/建议优化。
   可以筛选、按时间或优先级排序，复制或导出 Markdown 给外部执行者。
5. 导入修复版本，关联同一作品分组的版本，选择待复查；人工复查后选择已解决并保存。
   原始反馈与状态处理历史均保留。必须修改的意见关闭后，用户可明确点击确认版本验收。
6. 「发布复盘」手动填写平台、时间、成片版本、链接、耗时、支出与经验；每次观察独立添加指标快照。
   未知值为空/null，明确填写 0 才代表零。
7. 更多菜单支持归档、重新打开、移除记录；移除前明确提示，原文件和外部目录不删除。

## 数据与备份

`workspace.json.creationProjects` 默认空数组；沿用 WorkspaceStore 自动备份、临时文件写入与原子替换。
保存失败回滚工作室内存记录。旧工作区、旧快照和旧完整备份缺少此字段时正常打开。

Project 包含身份、名称、目标、简报、八个制作阶段、目录、外部身份、来源版本、时间、归档、选定版本与活动。
Task 包含身份、目标、任务状态、产物关联、阻塞原因及时间；第一版从外部结构记录导入。
Run 包含独立执行身份、来源、说明、状态、任务、起止与心跳时间、帧数、错误和可选资源采样。
Artifact 包含独立版本身份、作品分组、类型、标签、路径/本机 URL、来源、来源版本、SHA-256、大小、任务/执行与人工验收记录。
Review 固定关联原产物版本，可选秒数，保留问题、期望、优先级、状态、修复版本摘要与处理历史。
Publication 固定关联发布版本，保存发布时间、链接、耗时/支出/经验，以及带独立观察时间的指标快照。

所有结构通过字段白名单清洗，不保存外部记录的未知字段（如 apiKey、env、command）。
自由填写的简报、错误或意见不要包含密钥；执行器必须在写入前脱敏。
最多 100 项目，每项目每类记录最多 500 条，活动保留最近 80 条。记录过多拒绝保存，不静默覆盖旧版本。

视频、图片、源码、缓存与权重不写入主数据，也不打包到工作室备份；工作室备份只保存索引、意见和发布记录。
外部媒体请另行备份。现有「包含资料文件」仍仅适用于资料库，不代表包含创作媒体。
恢复后目录/文件失效会单独提示；不会自动扫描磁盘寻找文件。

## 外部记录协议 1

在用户明确关联的目录下放置固定名称 `workbench-record.json`，UTF-8 JSON，最大 1 MB。
可直接试用的独立目录见 [`../examples/creation-record/`](../examples/creation-record/README.md)：
新建空项目后关联这个目录并刷新。不会自动插入正式工作区。

```json
{
  "schemaVersion": 1,
  "projectId": "my-project",
  "sourceVersion": "git-sha-or-manual-source-1",
  "updatedAt": "2026-11-05T12:00:00Z",
  "tasks": [{ "id": "render", "goal": "输出第一个版本", "status": "review" }],
  "runs": [
    {
      "id": "run-1",
      "source": "local-render-script",
      "taskId": "render",
      "status": "completed",
      "description": "真实执行完成后才写此状态",
      "startedAt": "2026-11-05T11:59:00Z",
      "endedAt": "2026-11-05T12:00:00Z",
      "updatedAt": "2026-11-05T12:00:00Z",
      "frames": 240,
      "totalFrames": 240
    }
  ],
  "artifacts": [
    {
      "id": "film-v1",
      "family": "成片",
      "type": "video",
      "label": "v1",
      "path": "output/film-v1.mp4",
      "taskId": "render",
      "runId": "run-1",
      "sourceVersion": "git-sha-or-manual-source-1",
      "createdAt": "2026-11-05T12:00:00Z"
    }
  ]
}
```

上例用于说明字段，成片路径应指向你实际生成的文件，不能以样例伪造执行。
`schemaVersion`、`projectId`、`updatedAt`、三个数组是必填项，空数组合法。
项目/记录 id 为非空且不超过 100 字符的稳定字符串，同类 id 不重复。任务与执行状态允许
`pending/running/review/blocked/completed/failed/cancelled/interrupted/unknown`。
执行必须提供有效 `updatedAt`；有 `totalFrames` 时需为正整数，`frames` 为 0 至总数的整数。
不提供帧数就不显示百分比。`taskId/runId/artifactId` 引用必须存在。
可选资源字段为 `memoryMB/vramMB/sampledAt/scope`，范围应说明进程、渲染器或设备；未提供显示未提供。
Task 可提供 `createdAt/updatedAt/blockedReason/artifactId`，Run 可提供 `error`（已脱敏）。

产物 `type` 支持 `image/video/text/interactive`，版本 `label` 必填，`family` 默认作品。
非互动作品的 `path` 必须为关联目录内相对路径；拒绝绝对路径、`..`、NTFS 流与越界符号链接。
图片支持 PNG/JPEG/WebP（最多 50 MB），视频支持 MP4（最多 4 GB），文字最多 1 MB。
检查扩展名、文件头、大小、读取权限和写入期间变化；MP4 编码是否能播放由 Electron 解码器决定。
缺失文件保留路径记录并显示文件已丢失。文件第一次生成后若摘要变化，应写新的产物 id。

互动产物使用 `url`，只接受无凭据、无查询与片段的 `http://127.0.0.1:端口/路径`、`localhost` 或 `[::1]`。
用户显式点击后在外部默认浏览器打开，不内嵌运行、不注入 preload、不负责启动服务器，也不能凭 URL 验收。

刷新先校验整份记录，再一次性提交。按外部项目身份+记录 id 生成稳定内部身份，重复刷新不会重复创建。
已有版本的摘要、路径、URL 或来源版本变化时拒绝本次刷新，要求使用新产物 id；保留旧版本和反馈。
较旧时间、错误 JSON、错误引用、无权限与异常路径均保留最后有效数据，并显示原因。
项目阶段和人工验收状态不能由协议修改。BRIEF/HANDOFF/QA/README.md 可只读查看，不解析成执行状态。

执行器写入时使用临时文件与原子 rename，产物写完后再登记；可先保留旧 artifacts 列表并追加新版本。
工作室不监听目录，需手动刷新。外部记录中的 running 仅表示已收到声明，超过 120 秒无心跳、未来时间异常，
或 Workbench 重启后未再次刷新，显示「状态待确认」。界面每 30 秒更新陈旧状态，不探测进程、不推断成功失败。
完成、失败、取消、中断与未知分别展示；显示实际帧数不代表最终验收。

## 预览与验收边界

媒体经主进程校验后发放会话级 `studio-media` 能力 URL，流式读取以支持 MP4 seek，不转 Base64。
请求只服务已登记媒体，检查索引与文件 size/mtime，拒绝文件变动；渲染层无文件系统或任意命令能力。
文字只作为转义后的纯文本显示，Markdown/HTML 不执行。系统文件选择器负责明确授权手动导入路径。

预览/人工确认/意见关闭时重新核对 SHA-256。文件丢失或被替换不展示已验收。
来源版本变化后，旧人工验收记录保留，但不代表新来源通过；新产物始终待验收。
修复文件变化后原意见处理记录保留，显示需重新复查。备份恢复不证明外部文件仍存在。

## 验证与下一阶段

单元测试覆盖存储、失败回滚、备份、协议幂等、事务失败、路径/权限、文件摘要、意见与指标；
真实 Electron E2E 覆盖创建/重启、文件 IPC、图片对比、真实 H.264 MP4 播放/seek/双版本同步、
6.2 秒反馈和定位、复制、用户验收与发布快照。截图输出系统临时目录 `zp-creation-qa`。
测试使用隔离用户目录和合成媒体；不访问真实用户工作区或付费 API。
Windows 原生文件选择器另以 Computer Use 实测导入隔离 MP4，并在本机界面播放至 8 秒结尾。
最终完整门禁通过：215 项单测与 38 项 Electron E2E，静态/类型/格式检查、构建和文档镜像通过；源码行覆盖率约 88%。
一次全量回归中，既有 PPT 用例点击临时任务条按钮时，按钮已自动消失而超时；不修改用例，单独复跑通过。

真实项目的大视频性能、其他 MP4 编码、原生目录选择器完整操作、本机互动作品实开、
被系统拒绝的选择器权限、人工审美与长期使用待用户验收。
未来 Codex/渲染器只需写上述协议。若要接入执行命令、取消、进程身份或素材权限，应另立规格，
显式授权与隔离，不能将本轮导入接口扩大为任意命令或任意路径读取。
