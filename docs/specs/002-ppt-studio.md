# 002 PPT 工作室

> 状态：已实施（对话创作基础版；真实模型与 Office 人工验收待完成）

## 背景

ZP Workbench 将逐步扩展为帮助用户完成实际交付的本地工作台。用户要求新增独立的工具导航，
把 PPT 制作放入其中。职业规划比赛是首个使用场景，但产品面向商业提案、工作汇报、教学、
技术分享、品牌展示和比赛答辩，不限定为学习工具。

## 长期方向与调研

目标是具备内容策划、视觉设计、精确修改与可靠交付能力的演示设计工作室。
已调研 Presenton、PPTist、PPTAgent、PPT Master、Banana Slides、SlidePoise 和 Deckium：
参考完整创作流程、原生编辑、视觉复核和可编辑对象重建方法。调研未安装运行这些项目，
不把 README 的能力声明写成兼容性实测结论，也不直接复制第三方项目代码。

## 第一版目标

- 左侧新增「工具」分组与「PPT 工作室」。
- 新建、保存、重新打开、删除作品；本地工作区及快照/完整备份保留作品。
- 一个对话输入框直接接收比赛通知、项目材料和想法，不再要求先填写主题、听众、页数等表单。
- 模型从材料推断要求、结构、场景、页数和主题；缺少关键信息时集中追问，信息足够时直接生成
  3–16 页初稿进入预览。提示词要求不编造事实，不能把提示词约束视作已经完成事实核验。
- 后续对话携带当前作品和所选页面，支持按页面 id 局部修改、整套主题修改，以及明确要求下的
  页面结构调整；修改可撤销、重做，只有保存才写入工作区。
- 手动编辑按需展开，无模型也可从空白作品开始；三种视觉主题、五种版式，支持标题、正文、
  要点及演讲备注。
- 调整页面顺序、复制/删除页面、撤销/重做；切换作品前处理未保存内容。
- 同一结构化布局生成预览与可编辑 PPTX。导出前提示内容密度，文字和形状不整页栅格化。
- 模型只收到用户主动提交的本次对话与当前作品，不读取资料库正文；模型输出不自动入库。

## 本轮边界

这是工作室基础版，不宣称已达到全部长期目标。暂不包含任意 PPTX 导入、自由拖拽画布、
图片生成、图像重建、原生数据图表、复杂动画、HTML/PDF 导出和模型视觉自动审查。
PowerPoint/WPS 真实显示与人工审美验收保留为待用户验收。
本轮升级对话入口与创作/修改流程，图文表达能力仍受现有主题、版式和文字/形状引擎限制。
对话材料仅保留在本次编辑会话，离开作品或重启后不恢复；保存、备份仍只包含作品内容。

## 方案

- `src/shared/presentation.mjs`：数据约束、主题、场景、版式和布局，主进程与渲染层共用。
- `WorkspaceStore` 在 normalizeData 中兼容 `presentations`，旧工作区默认为空；正式写入先备份，
  原子保存失败则恢复内存中的旧作品；已有作业、知识点兼容数据不改变。
- `src/main/presentation-export.cjs`：PptxGenJS 输出原生文字与形状，通过主进程保存对话框导出，
  临时文件写入完成后原子替换目标，取消和失败不影响作品。
- 白名单 IPC：保存作品、删除作品、对话创作、导出作品；旧大纲接口保留兼容，界面不再使用。
  `presentation:chat` 经 preload 的 `chatPresentation` 调用，主进程先校验再发模型请求。
- `src/main/presentation-chat.cjs`：消息最多 12000 字，上下文最多 20 条、48000 字；渲染层保留
  首次材料与最近对话，始终单独提交当前作品。只接受 clarify/create/edit 三类 JSON 结果。
  局部修改校验页面 id 与字段白名单，完整替换需独立结构；保留作品身份、未修改页面和备注。
  回复不执行代码、不直接持久化；并发请求共用生成锁，失败保留输入与原稿，可直接重试。
- `src/main/presentation-ipc.cjs` 独立注册作品接口，另接受布尔值的未保存状态信号，真正退出
  应用时由主进程提示返回保存。导出依赖的 `image-size` 固定到已修复的 2.0.4。
- 页面沿用依赖注入，不引入 UI 框架；预览 API 明确为示例生成，不调用真实服务。

## 验收标准

- [x] 工具导航可进入工作室，空状态可直接开始创作。
- [x] 编辑、顺序调整和备注保存后，重启仍可恢复。
- [x] 取消删除、取消离开及生成失败保留现有草稿。
- [x] 粘贴通知后可以回答追问并直接得到预览，无需填表或单独采用大纲。
- [x] 对话修改当前页、撤销重做、无效结果恢复和重新打开作品后隔离对话有自动化验证。
- [x] 模型输出只更新可撤销草稿，只有保存才写入本地。
- [x] 无模型也能完成手动创作与 PPTX 导出。
- [x] 输出 PPTX 包含可编辑文字、形状、正确页面顺序及演讲备注。
- [x] 旧快照导入、备份重载及现有功能回归通过。
- [x] 深浅主题、窄窗口、长文本、键盘操作有自动化验证；真机显示待用户验收。

## 测试与风险

模型 JSON、边界和并发、工作区重载/备份、导出 OOXML 与 Electron 交互分别测试。
2026-10-28 对话版验证：`npm test` 151 项、全量 Electron E2E 26 项（含 PPT 6 项）与
`npm run verify` 通过，含切页后异步生成/保存完成时未保存状态信号的回归测试。
基础版此前运行时依赖审计 0 漏洞，本轮未新增依赖。
PPT AI 流程使用本地模拟模型，未调用真实用户模型，真实生成质量待用户验收。
预览和 PPTX 使用相同布局坐标，但字体与不同 Office 阅读器可能造成换行差异，不能宣称像素级保真。
回滚代码时先导出包含 presentations 的快照；旧版本不认识新字段，不应使用旧版本再次保存新作品。
