# 功能规格（specs）

每条新功能或较大的改动，先在本目录建一份规格文件，再动代码。文件名用
`NNN-短名称.md`，序号递增。线程可以关掉、可以压缩，规格文件不会。

> 状态约定：规格文件开头写一行 `> 状态：进行中 / 已废弃 / 已实施`。
> `001` 是已停止方向的历史规格，只作背景；当前架构、边界和开发方式以
> `docs/DSH_HANDOFF.md` 为准，不要照着 `001` 恢复工具台、应用托管或 Computer Driver。

模板：

```markdown
# NNN 功能名称

## 背景

要解决什么问题，谁在用。

## 目标

- 可验证的结果 1
- 可验证的结果 2

## 非目标

这次明确不做什么。

## 方案

关键数据结构、IPC 接口、涉及模块（`src/main/...`、`src/renderer/main.js`）。

## 验收标准

- [ ] 步骤 → 预期结果
- [ ] 边界情况：空数据、超大文件、重复导入

## 风险与回滚

数据迁移、兼容性、回滚方式。

## 测试

新增或修改的 `tests/*.test.cjs`。
```
