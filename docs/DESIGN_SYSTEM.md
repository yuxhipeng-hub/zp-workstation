# ZP Workbench 设计系统

这份规范用于约束 ZP Workbench 的桌面界面。它吸收了 `awesome-design-md`
中的 Raycast 参考样本，并结合 `ui-ux-pro-max` 的交互、可访问性和实现建议，
但最终服务于 ZP 自己的黑白工作站定位。

## 1. 设计目标

- 像桌面生产力工具，而不是营销落地页。
- 信息密度高，但层级和扫描路径清楚。
- 以近黑、纯白和中性灰为主，不依赖彩色光斑或大面积渐变。
- 动效短、直接、连续，不通过夸张弹跳制造“活泼”。
- 同一组件在不同页面保持一致的高度、圆角、边框和焦点状态。
- 尽可能去掉不必要的小字注释：默认不显示重复介绍、操作常识、技术实现说明和无助于判断的提示。
  必要的来源、时间、错误与操作反馈保留；不能用缩小字号或降低对比度代替删减。

## 2. 主题与表面

支持深色、浅色、跟随系统三种模式。颜色只通过 CSS 变量使用。

### 深色主题

| 层级     | 变量             | 用途             |
| -------- | ---------------- | ---------------- |
| Canvas   | `--bg`           | 应用画布         |
| Rail     | `--rail`         | 左侧导航         |
| Elevated | `--bg-elevated`  | 顶栏、表格底     |
| Surface  | `--panel`        | 卡片、面板、弹窗 |
| Raised   | `--panel-raised` | 输入框、内嵌区块 |
| Hover    | `--panel-hover`  | 悬停             |
| Active   | `--panel-active` | 选中和按下       |

表面之间主要靠背景层级和 1px 边框区分。阴影只用于弹窗、浮层和很轻的
悬停反馈，不用于装饰普通卡片。

## 3. 颜色

- 主操作：`--ink`。深色主题为白色，浅色主题为近黑色。
- 正文：`--text`。
- 次要文字：`--text-secondary`。
- 元数据：`--text-tertiary`。
- 分割线：`--line`。
- 强边框：`--line-strong`。
- 状态色只用于状态、错误、成功和警告，不作为大面积装饰色。
- 品牌字母 `zp` 是唯一允许使用循环彩色的品牌元素。

禁止把大面积青、紫、蓝渐变用作页面背景。点状背景是允许的结构性纹理，
但透明度必须很低。

## 4. 字体与层级

- UI 字体：`Workstation UI` 本地字体栈。
- 数字和代码：`Workstation Mono`。
- 正文基准：14px。
- 页面正文：12px，行高 1.6 左右。
- 元数据和标签：9-10px，仅用于辅助信息。
- 页面标题：23-24px，字距不收紧到影响中文阅读。
- 卡片标题：14-18px，避免在紧凑面板中使用展示级字号。

所有文字必须允许换行或省略，不能让标签、按钮文字或动态内容撑破容器。

## 5. 圆角与间距

| Token         | 值   | 用途                 |
| ------------- | ---- | -------------------- |
| `--radius-sm` | 8px  | 按钮、选项、图标容器 |
| `--radius`    | 12px | 筛选触发器、分段控件 |
| `--radius-lg` | 16px | 页面表面、弹窗和浮层 |

- 圆角复用 `ui-refresh.css` 中的共享 token，不在页面里另造一套。
- 常规控件沿用共享组件高度；榜单的紧凑工具栏按第 9 节使用 30/32px。
- 页面内容块间距以 8px 为基本单位。
- 卡片内部优先使用 14-24px 内边距。

## 6. 控件

### 按钮

- 主按钮：实心 `--ink`，文字使用 `--ink-inverse`。
- 次按钮：`--panel` 背景，1px 边框。
- 危险按钮：只在边框和文字使用危险色，不铺满高饱和红色。
- 悬停只改变边框、背景和颜色，不上下跳动。
- 按钮、导航和高频点击控件按下不缩放、不位移；图标也保持原位。
- 忙碌态保留文字、图标和尺寸，使用禁用/游标及已有任务反馈，不先隐藏文字再闪回。

### 输入框

- 默认背景为 `--panel-raised`，边框为 `--line`。
- 聚焦时边框变为 `--focus`，外圈为 3px 低透明焦点环。
- 占位文字必须保持可读，但不能与正式输入内容混淆。
- 文本框统一取消手动拖拽缩放手柄，长内容通过滚动或编辑器原有展开方式浏览。

### 导航

- 活动项使用 `--panel-raised` 背景、加强边框和清晰的文字颜色。
- 活动指示条只作为辅助，不能成为唯一状态线索。
- 悬停不改变布局尺寸。

## 7. 动效

| Token           | 时长  | 用途               |
| --------------- | ----- | ------------------ |
| `--motion-fast` | 110ms | 按下、图标反馈     |
| `--motion-base` | 170ms | 悬停、面板状态     |
| `--motion-slow` | 240ms | 弹窗、较大层级变化 |

- 使用 `cubic-bezier(0.2, 0.8, 0.2, 1)` 一类快速收尾曲线。
- 页面进入动画不超过 170ms，列表项错峰不超过 4-16ms。
- 不使用长距离位移、持续旋转和影响布局的动画。
- 保存、刷新和镜头切换不触发展开动效；重绘保留文本框高度，取消旧动画后才测量位置。
- 必须支持 `prefers-reduced-motion: reduce`。

## 8. 可访问性

- 键盘焦点必须可见，不能被 sticky 元素遮挡。
- 所有图标按钮必须有 `title` 和 `aria-label`。
- 正文与背景满足可读对比度；禁用态不能低到无法辨认任务内容。
- 颜色不是唯一状态表达，状态同时使用文字、图标或边框。
- 弹窗打开后焦点进入弹窗，关闭后返回触发位置。

### 对比度人工检查清单

每次改主题色、面板色或状态色后，在深色与浅色两个主题下各看一遍：

- 正文、标题、次级说明在面板背景上是否仍可读，尤其是 `--text-secondary` 一类弱化文字。
- 主按钮、次级按钮、危险按钮的文字与填充是否清楚；禁用态是否还能辨认内容。
- 状态徽章（成功 / 警告 / 危险 / 中性）在两种主题下是否都能区分，不只靠颜色。
- 焦点环在面板和彩色卡片上是否可见。
- 日志控制台、代码块和深色卡片的文字不被背景吃掉。

截图或人工确认的结论写进当次 PR 说明，不需要单独存档。

## 9. 榜单与资讯列表：已确认的视觉基准

2026-11-06，用户认可 GitHub 发现页本轮 UI。后续同类榜单、资讯列表和筛选工具栏
以此为设计基准；表单、编辑器等其他场景按其任务需要选择密度。
实现参考 `src/renderer/github-discovery.css` 与 `src/renderer/components/github-language-picker.js`，
功能边界见 [GitHub 发现规格](specs/004-github-discovery.md)。

### 层级与留白

- 页面保留一个主要外框，内部靠留白和直线分隔，不重复套带边框的卡片。
- 顶栏已有页面标题时，内容区直接开始视图切换和操作，不重复标题或介绍。
- 页面内边距：上下 24px、左右 26px；窄窗口为上下 20px、左右 16px。
  增加包装容器后也必须保留这层留白，文字、图标和控件不得贴外框。
- 工具栏紧凑，外框留白充足；缩小控件时不同时压缩页面留白。
- 视图页签与刷新占第一行，周期与语言筛选占下一行；组内有联系，组间留出 12–20px。
- 列表用低对比度横向分隔线；条目上下留白约 18px，标题、描述、元数据依次排列。
  长标题允许换行，描述默认至多两行，展开后读全文。

### 控件密度与状态

| 控件       | 高度 / 字号 | 表现                                                 |
| ---------- | ----------- | ---------------------------------------------------- |
| 视图页签   | 30px / 12px | 文字页签；活动项加强文字并加下划线，不做独立大按钮   |
| 周期切换   | 30px / 12px | 同一分段底座；活动项用中性填充与字重区分             |
| 刷新       | 30px / 12px | 轻量图标加文字，不与主要内容争抢视觉权重             |
| 筛选触发器 | 32px / 12px | 文字加箭头；默认轻量，悬停或展开时才加强背景与边框   |
| 菜单选项   | 32px / 12px | 左侧文字、右侧选中勾；悬停、选中、键盘焦点均清楚可见 |

列表标题约 14px，描述 12px，元数据约 11px。元数据集中成行，不散落多处。
只保留帮助阅读或操作的信息：来源、采集时间、条目数和必要状态。
不添加重复说明、常驻技术注释或占位功能；空状态只需清楚说明当前情况及可用操作。
说明确实有用但不必常驻时，放到相关详情或按需帮助中；主页面优先展示内容和可执行操作。

### 筛选浮层

- 同类筛选菜单使用主题一致的圆角浮层，避免直接呈现风格突兀的系统原生选项框。
- 触发器用 `--radius`，菜单用 `--radius-lg`，选项用 `--radius-sm`；不使用生硬直角矩形。
- 菜单默认宽 208px、内边距 6px，选项左右内边距 10px；贴近触发器展开，间隔约 8px。
- 浮层可用轻阴影和 1px 边框，普通列表不增加装饰阴影。
- 菜单按视口定位，四周至少留 16px，最高 280px；空间不足向上展开，超长列表内部滚动。
  滚动条用约 4px 的中性圆角滑块，不出现粗重轨道和上下箭头。
- 使用顶层浮层避免被内容容器裁切。支持方向键、Home/End、Enter、Esc、Tab 和点击外部关闭；
  选择或 Esc 后焦点回到触发器，键盘焦点不能因精简视觉而消失。

### 切换与验收

- 切榜、筛选、刷新只更新必要区域，保持外框、控件、滚动位置和键盘焦点稳定。
  加载期间保留内容高度，后台刷新不能突然关掉正在操作的筛选菜单。
- 完成后检查深浅主题、窄窗口、长文本、空状态和加载状态；实际展开菜单检查圆角、留白、
  滚动条与视口边界，同时确认切换过程中页面没有强制跳跃。

## 10. 资料关系

- `docs/RAYCAST_DESIGN_REFERENCE.md`：外部品牌设计样本，只作参考。
- `docs/DESIGN_SYSTEM.md`：ZP Workbench 的实际实现规范。
- `ui-ux-pro-max`：通用 UI/UX 规则、可访问性检查和实现建议。

两者职责不同，不冲突。外部样本不能覆盖 ZP 的多主题、黑白主视觉和已有功能边界。

## 10. 创作工作室画布

创作页是 `route-canvas` 的明确例外：背景就是画布，采用「项目→视频→编号步骤」的纵向树形大纲。
点阵只由应用主背景 `#app` 绘制。创作页标题栏、工具栏和树形容器透明，禁止内部重复铺点阵或实色底板。
步骤名称、负责人、记录状态按列对齐；实际镜头挂在分镜步骤下，不再使用七宫格职责卡片。
大纲在画布中水平居中，随窗口加宽至1440px；展开、收起与切换保持当前视口，不自动滚动定位。
项目、视频和镜头分支各自展开，展开不触发任务；点步骤或镜头才在对应行下打开编辑框。
操作图标紧邻对象名称，项目管理收进三点菜单；编辑框紧跟来源对象，再次点击原入口收起并保留草稿。
不加重复列头或层级路径小字。项目菜单沿用第9节的纵向主题浮层，不使用横排胶囊按钮，不挤动树形内容。
缩放/重置固定在窗口右下角，不显示整行底栏或拖动提示。
保存等主要操作采用透明底文字/图标按钮；滚动条轨道透明，保留滑块。制作阶段使用同主题选择浮层。
视频行明确区分「手动阶段」和「作品版本数」，不把记录数量或手动标记呈现为 Agent 执行进度。
不加包围整个页面的大卡片，不加常驻属性栏。展开编辑框和菜单使用无描边的整块底色；
浮层先隐藏定位，再同步显示，不从默认位置平移动画；按钮键盘焦点用细灰线，表单及外层标签无描边或光晕，只保留灰色底线。
需求框最多320px宽，默认不超过260px高，目标与阶段并排折叠，展开后最多312px高；
创作要求空白时为单行，随内容增减高度，上限112px后内部滚动，不固定预留两行。
七步骤下面继续使用内容树，默认阅读、展开叶节点看实际结果；最多再加两层，不把每个参数拆成节点。
内容树透明，不套编辑卡片，不重复标题或操作说明；编辑图标按悬停/键盘焦点显示，触摸设备常显。
手动制作详情沿分支宽度展开，自然高度与画布统一滚动；左侧编辑区最多520px，右侧展示对应内容，窄屏上下排列。
每个展开步骤只保留自己的功能；提示词编辑归入分镜，审核只读，其他步骤工具从视频行入口进入。
图片/视频只展示明确关联的具体版本，不用其他未关联作品补位。
创作沟通使用Codex主对话框，页面不内嵌导演聊天；审核模型设置仅在审核与后期步骤按需展开。
加宽不放大间距，表单行距10px、列距16px；制作文本框从单行按内容增高，最多180px，删除后缩回。
宽屏总览并排展示作品与制作信息；需求小框继续保留尺寸上限与内部滚动。
加号打开需求框，保存后收起，需求操作重新打开；镜头草稿独立保留，Esc收起并返回来源节点。
复杂参数按需显示。图片、分镜和视频是主要内容，控件使用阅读宽度与间距组织。
具体交互、旧数据兼容与职责边界见[规格003](specs/003-creation-studio.md)。
