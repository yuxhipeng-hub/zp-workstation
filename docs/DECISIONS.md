### 2026-10-25 模型预设只填接口地址，不承诺模型能力

- 背景：模型和厂商更新很快，应用不可能为每个新模型硬编码能力；但用户也不想每次都翻文档
  找 Base URL。
- 决定：模型配置维护国内外主流 OpenAI Compatible 厂商的 Base URL 预设，并提供自定义入口；
  预设不填具体模型 ID（`deepseek-chat` / `deepseek-flash` 这类稳定 ID 除外），也不默认
  勾选视觉能力。只有 `deepseek-flash` 预设自动勾选「支持视觉输入」，其他厂商由用户按实际
  模型勾选。
- 代价 / 放弃的方案：用户仍需知道模型 ID，预设地址也可能随厂商调整；换来的是新模型发布
  不用改应用，也不会因为预设写死而过期。非 OpenAI Compatible 的原生接口（如 Claude、
  Bedrock）仍需走兼容网关或自定义。

### 2026-10-25 作业智能录入支持通知截图

- 背景：很多课程作业只发布在学习通、教务系统等平台，用户拿不到可复制的文字通知，只能
  截图。原有的纯文字抽取无法覆盖这类场景。
- 决定：智能录入支持粘贴、拖入或选择最多 2 张 PNG/JPEG/WebP 截图，和文字一起发送给当前
  模型；渲染层先把图片等比压到最长边 2000 的 JPEG，主进程只接受受控的 data URL 并校验
  类型、数量和大小。模型档案必须勾选「支持视觉输入」才会启用；内置 `deepseek-flash`
  （DeepSeek V4.1 Flash）视觉预设，选中后自动勾选该能力。仍然先返回 JSON 草稿，
  用户勾选确认后才写入收件箱。
- 代价 / 放弃的方案：图片只发送给用户自己的模型，不落盘、不写日志、不进入工作区或备份；
  不支持视觉的模型仍需使用文字。没有引入本地 OCR，也没有做后台抓取平台。视觉模型按图片
  计费，长截图和多次重试的成本由用户自己控制。

### 2026-10-25 作业智能录入采用“抽取草稿 + 人工确认”

- 背景：录作业是收件箱最高频的摩擦；模型接入后可以代读群通知，但通知里常混有非作业内容，
  截止日期也常写成“下周五”这类相对时间。
- 决定：只把用户粘贴的这段文字和当天日期发给当前模型，要求输出严格 JSON 草稿；最多 5 条，
  日期只接受 `YYYY-MM-DD`，优先级只接受 `low/medium/high`，标题必须来自原文。草稿先在
  作业页列出，用户勾选并点击添加后才通过 `WorkspaceStore` 写入。课表、资料库、工作区其他
  字段都不会进入这次提示词。
- 代价 / 放弃的方案：不做后台自动抓取，也不在解析时直接落库；用户仍需粘贴一次并核对日期。
  换来的是未确认前不写库、可以随时取消，模型输出也不会被自动执行。

### 2026-10-24 DSH 上下文改为分层按需加载

- 背景：`HANDOFF.md` 长期同时承载动态状态、发布记录和完整变更表，DSH 接手时还需要再读一份
  架构手册，入口越来越长；把同一状态复制到多份文档也会持续漂移。
- 决定：`docs/HANDOFF.md` 只保留当前状态、当前待办和最近任务，完整历史移入
  `docs/HANDOFF_ARCHIVE.md`；根 `AGENTS.md` 只做总路由和跨目录红线，`src/main/`、
  `src/renderer/`、`tests/` 通过目录级 `AGENTS.md` 提供局部约束；项目级
  `.dsh/skills/zp-workbench/SKILL.md` 只在开发任务中按需加载。DSH 仍是开发工具，不进入
  ZP Workbench 产品运行时。
- 代价 / 放弃的方案：规则分散在多个文件，改目录约定时要同步维护对应局部文件；换来的是
  每个任务只载入所在目录相关内容，交接页和架构手册不再无限增长。

### 2026-10-24 暂不采购代码签名，用发布说明处理 SmartScreen

- 背景：安装包一直未签名，Windows SmartScreen 会拦；采购代码签名证书大约需要 200–400 美元/年，
  还要处理证书保管和 CI 注入。
- 决定：当前不购买证书；在 README 和每个 Release 说明里写清 SmartScreen 提示的原因和
  「更多信息 → 仍要运行」的操作方式，并保留 `.sha256` 供用户校验。
- 代价 / 放弃的方案：首次安装会多一步确认，部分用户可能因此放弃；等安装量或分发范围变大，
  再重新评估证书预算。

### 2026-10-23 更新下载降低并发并从限流线路撤离

- 背景：`0.6.0` 发布后，更新器在 `gh-proxy` 等镜像上频繁收到 HTTP 429；默认 8 路并发、
  64 个分片、8 路测速和 256 KB/s 的单连接慢速阈值会把仍可下载的线路判死，回退单线路时又
  容易再次撞上同一条被限流线路。`gh.xxooo.cf` 当前已无法解析。
- 决定：默认并发降到 4，分片降到 16，测速连接降到 1，单连接慢速阈值降到 64 KB/s；下载器
  记录每条线路的 429 冷却时间，在冷却期内不再给新分片分配这条线路。移除已失效的
  `gh.xxooo.cf`，保留 GitHub 直连、`gh-proxy.com` 和 `ghfast.top`。
- 代价 / 放弃的方案：峰值并发和动态拆片能力下降，网络极好的机器可能比 8 路连接稍慢；
  换来的是镜像限流概率明显降低、慢速线路不会拖垮整次下载，回退单线路时也会优先避开刚刚
  返回 429 的线路。

### 2026-10-21 模型配置从设置拆为独立板块

- 背景：模型档案包含协议、Key、能力参数和连接测试，继续放在设置页会让设置变成模型管理器，
  也不利于从作业页直接跳转配置。
- 决定：系统分组新增独立「模型配置」页，展示当前模型、协议、连接状态、模型档案列表和详情编辑；
  设置页只保留当前模型摘要与入口。设置页同时合并数据存储、移除重复的备份操作，快照和文件
  校验迁到既有「备份与同步」页。
- 代价 / 放弃的方案：导航多一个入口，模型配置与普通偏好分成两页；换来的是配置空间完整、
  作业缺模型时跳转明确，备份和模型工具不再与设置页重复维护。

### 2026-10-21 AI 接入采用模型无关的直接调用

- 背景：赛道要求 AI 真正参与产品流程，原先只在作业收件箱复制提示词，用户仍需切换到外部
  工具；不同同学使用的模型服务也不一定是 DeepSeek。
- 决定：新增 OpenAI Compatible 直接调用层，支持多个模型配置档案、任意 Base URL 和模型 ID；
  模型档案区分 Chat Completions / Responses 协议，并保存上下文窗口、输出上限、温度、推理
  强度、超时、工具/视觉能力标记与非敏感附加请求头。API Key 通过 Electron `safeStorage`
  单独加密保存，不进入 `workspace.json`、日志、快照或完整备份。首版 AI 能力聚焦作业拆解，
  把步骤、前置条件、风险与检查清单保存到作业数据。DSH Headless 暂不进入基础链路，仅作为
  后续可选 Agent 引擎评估。
- 代价 / 放弃的方案：远程模型需要网络和用户自己的 Key，不承诺所有厂商的原生协议；首版不做
  AI 聊天、资料正文抽取、工具调用、自动执行、跨供应商聚合和权重路由。换取的是接口边界清楚、
  可测试、不会把用户数据无条件发送给固定服务商。

### 2026-10-21 日志跨重启恢复，Windows 安装固定为每用户

- 背景：日志文件一直在 `workbench.log`，但界面启动时只读取内存，重启或更新后看起来像日志
  全部消失；Windows 安装器又允许当前用户和所有用户两种安装模式，遗留了同一 GUID 的两套注册
  记录，升级时可能重新注册快捷方式并导致桌面快捷方式重建、任务栏固定项失效。
- 决定：`Logger` 启动时从日志文件尾部回读最近 1 MB，恢复最近 800 条记录；NSIS 安装器设置
  `allowElevation: false`，只允许每用户安装，但保留自定义安装目录。`appId`、`productName`、
  `shortcutName` 和 `guid` 继续作为稳定身份，新增测试禁止无意修改。
- 代价 / 放弃的方案：安装器不再提供“所有用户”安装；已存在机器级和用户级重复安装记录的电脑
  需要一次性手动清理旧记录，然后重新固定任务栏。这样换来后续原位升级不再分裂 AppUserModelID，
  也不通过代码擅自删除用户的快捷方式或注册表。

### 2026-10-15 资料库只负责归档，正文不抽成提示词

  多份资料的取舍这些边界。`document-text-extractor.cjs` 继续只服务课表解析。

### 2026-10-15 知识库由仓库生成，不手工维护副本

- 背景：需要给项目建一个 Obsidian 知识库，把散在仓库里的资料集中起来看。直接在 vault 里
  维护一份手抄副本会立刻开始漂移，交接说明这类文档每次任务都在改。
- 决定：仓库文档仍是唯一真实来源，vault 由 `scripts/sync-obsidian-vault.mjs` 生成：
  文档逐份镜像成笔记，`docs/HANDOFF.md` 的「最近任务」「当前待办」抽成独立笔记，完整历史
  由 `docs/HANDOFF_ARCHIVE.md` 单独镜像，另外生成 Bases 汇总视图和
  资料关系画布；手写笔记的正文放在 `docs/vault/`，随仓库一起走版本管理。
- 代价 / 放弃的方案：知识库不能当第二个编辑器，在 vault 里改生成笔记会被下次同步覆盖；
  每次改完仓库文档要多跑一条 `npm run sync:vault`。换来的是 KB 结构可再生、来源可追溯，
  文档改名时测试会立刻报错。

### 2026-10-14 今日页接入 AIHOT 资讯

  再分发需要另行授权；因此面板只做本地展示与外链，保留 AIHOT 署名和原文入口，不把内容
  写进导出、备份或任何对外产物。网络不可用时显示缓存并在标题下方标注离线。

### 2026-09-23 课表数据写入走应用代码路径

- 背景：需要把外部 Excel 课表里的课程并入用户现有课表，直接编辑
  `workspace.json` 容易破坏结构或漏掉课程库关联。
- 决定：用 Node 加载 `WorkspaceStore` 与 `ScheduleManager`，调用 `createCourse()` 写入，
  写入前做手工备份，并保留应用的自动备份。
- 代价 / 放弃的方案：不采用脚本直接改 JSON 的方式；需要在写入前确认目标应用是否在运行，
  否则运行中的进程可能用内存旧数据覆盖文件。

### 2026-09-23 修正 DeepSeek 上下文窗口

- 背景：Codex 模型目录里 `deepseek-flash` 声明为 272K 上下文，实际模型支持 1M，
  导致压缩过早、反复丢上下文。
- 决定：把模型目录的 `context_window` / `max_context_window` 改为 1048576，
  `auto_compact_token_limit` 设为 800000，并在 `config.toml` 中写入同样的值。
- 代价 / 放弃的方案：长线程每轮输入更大，缓存未命中时单次成本更高，
  因此配套要求保持提示词前缀稳定、按功能切线程。
